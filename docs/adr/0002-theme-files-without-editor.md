# Theme files without an in-app editor

Spec 007 ("App themes") shipped on a "Presets only" answer: a built-in list of complete dark themes, explicitly no colour editor and no import or export (`specs/007-app-themes/spec.md:17,269`). The #474 design grill (agenda item 9, #458) decided to add theme files after all: a theme is a JSON file of palette/semantic-role/component-token overrides, loaded from the user's profile folder and listed in Appearance beside the built-in presets, with import and export and a validity-plus-contrast check on load — but still **no in-app colour editor**; a theme file is always authored outside Refract.

This is hard to reverse once the loader, validator, and Appearance UI exist, surprising to a reader of spec 007 who will find the opposite answer recorded there, and a real trade-off between three options: staying presets-only (simplest, but blocks a custom theme like the grill's own "hot-pink-bubble" example), building a full in-app editor (rejected — a colour-picking UI is a much larger surface than Stuart wants to build or support), and theme files with no editor (chosen — gets custom themes without building or maintaining a picker, at the cost of every theme being hand-authored as JSON). Spec 007 must be amended to drop its "Presets only" assumption before theme files are built; this ADR does not amend the spec itself.

**Consequences:** a theme file is untrusted input (constitution V) the moment import exists, so the loader, validator, and preload boundary must treat it that way; see "Untrusted input" under [Theme files](../design/foundations-tokens-theming.md) for the specific requirement (#580 quality-gate review).
