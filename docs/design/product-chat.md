# Product chat

Decided by Stuart in the #474 grill, 2026-10-08.

This page covers the chat transcript, the message box, composer behaviour, and in-chat formatting for a Session's Chat pane.

## Chat


- **Self vs. other layout** (Stuart, 2026-10-04): your ("self") messages render as a right-aligned bubble with a left indent, so a self message never touches the transcript's left edge, paired with a right-aligned avatar; the agent's ("other") text remains full-width, left-aligned, and sits plain on the background with no bubble -- the standing layout rule for anything rendered as the user's own content versus anything from the assistant or another agent. See **User message time** below for the muted timestamp above a self bubble.
- **Baseline collapsed line**: every output kind that is not a user/assistant-text message builds on one shared `CollapsedLine` component (`src/renderer/features/chat/CollapsedLine.tsx`): an icon slot, a short label, a one-line summary that truncates with an ellipsis, a status/duration slot, and (when there is something to expand) a `Collapsible` expansion whose trigger is a button with `aria-expanded`. A warning or error is always a distinct icon shape, never colour alone. A new output kind starts from this component instead of growing its own one-off collapsed row; `ToolRow`, `ToolGroupRow`, the Thinking line, the answered-question row, decided approvals, the subagent, agent-message, and advisory lines, and notices/command-output all build on it.
- **Transcript rhythm** (Stuart, 2026-10-04): `MessageScrollerContent` no longer sets a uniform `gap` (`src/renderer/components/ui/message-scroller.tsx`); each row carries its own top margin instead so the rhythm between turns/real user-assistant messages (`mt-6`) and the rhythm within a run of bookkeeping rows (`mt-1`) can differ -- a nested `gap-1` sub-list was the original idea, but `MessageScrollerItem` must stay a *direct* child of `MessageScrollerContent` (`@shadcn/react/message-scroller`'s scroll-anchor/visible-message tracking enumerates only `content.children`), which rules out wrapping a run in its own flex container. Consecutive rows built on the shared `CollapsedLine` baseline -- tool-group, thinking, advisory, notice, subagent, agent-message -- get the tight `mt-1` margin between each other; everything else (a user/assistant message, an `ask` question, a request/approval card, and the first row after one of those) gets the full `mt-6` rhythm, so the chat reads as the user<->assistant exchange first and bookkeeping rows as compact, secondary material.
- **Time-gap divider** (Stuart, 2026-10-04, new): a horizontal rule showing the date and time renders as its own transcript item between two turns whenever they cross a calendar-day boundary, or sit more than an hour apart on the same day, so a resumed-the-next-day or long-running session is visible at a glance. Keyed off each turn's own `user` item timestamp; omitted when either side has no usable timestamp (same rule as the turn-total-time line). When it renders directly above a user turn, that turn's own per-message time (**User message time** below) is hidden, since the divider already shows the same date and time.
- **User message time** (issue #555, decided 2026-10-16, `ui-architect-v3` roundtable; date rule amended 2026-10-16 by Stuart after the gate round 1 review; hidden-under-a-divider amended 2026-10-16, Stuart's second call): a small, muted `<time datetime>` row renders above every user bubble (`UserMessageRow.tsx`) -- a plain, unboxed row (the zero-box rule, `docs/design/components.md` "Cards and boxes"), right-aligned, never inside the bubble's own name header. Format, day-aware: today shows the bare time ("13:45"); yesterday shows the localised day word plus time ("Yesterday 13:45"); the same year shows day, short month, time ("14 Oct 13:45"); a different year shows day, short month, year, then the time after a comma ("16 Oct 2025, 13:14") -- all through the user's own locale (`toLocaleTimeString`/`toLocaleDateString`/`Intl.RelativeTimeFormat`, no hardcoded English words). Hidden entirely -- never a guessed value -- when the item's `at` is the sentinel `0` (a history entry OMP never timestamped, same rule the turn-total-time line below uses), when `at` is otherwise not a usable instant (an out-of-range timestamp), OR when the **Time-gap divider** above already renders directly above that same turn: the divider already shows the exact same date and time, so the row would just repeat it. Does not change turn-boundary spacing, which the existing **Transcript rhythm** bullet above already covers.
- Each tool call is one compact row: tool, target, status, duration. **Expanding no longer reveals boxed Arguments/Output or content** (#628/#630, 2026-10-11, supersedes this bullet's earlier "Expanding shows arguments and output"): it shows an edit's diff (capped to about 24rem with its own scroll and an Expand/Collapse control, #630), a successful `write`'s "Wrote N lines to `<path>`" line, or a short (single-line, 200 characters or fewer) successful result verbatim -- a successful `bash` call shows no output at all here (issue #632, 2026-10-17: only the Error line below carries a failed call's own exit/output text) -- plus a "View full call" text link, always present, with an accessible name including the tool and the target (truncated with an ellipsis, never dropped, past 80 characters), opening a dialog (`ToolCallDialog.tsx`, the `TextPreviewModal.tsx` pattern) with **Formatted** (a small header, each argument as its own labelled section -- a `write` call's own `content` re-parsed and pretty-printed when it is itself JSON, a `bash` call's own `command` highlighted as bash, every other string shown exactly as written -- then Output) and **JSON** (the exact arguments and output, pretty-printed, one Copy button) tabs. Never markdown (constitution V): every value is inert text or `CodeBlock`-highlighted code. An `edit` call's own row additionally shows a muted "+N −M" line stat (issue #632, 2026-10-17; `lib/diff.ts`'s `diffStat`, the same diff `DiffView`'s expanded body already computes) beside its duration -- `tabular-nums`, no colour (neutral even on a successful edit, #570's "success stays quiet"); no other tool (`grep`/`glob`/`find`/`read`/`write`) shows a count here, since none has a documented, fixture-backed output shape to probe first ("no count rather than a wrong one"). A failed call's own icon and label render in the error colour (issue #570, 2026-10-16; a `bash`/`grep` call's own label is dropped instead, #632 below, so the colour moves to its summary text) -- a successful or still-running call stays neutral ("failure loud, success quiet"). A failed call's error text is not part of this expansion at all: it is a baseline fixture, an **Error line** shown under the row whether collapsed or expanded (never hidden by the rule above), derived from the call's own output with control characters stripped (the last non-empty line for a `bash` call, after OMP's own trailing wall-time/exit-code footer is read for its exit status and then stripped, the first for any other tool).
- **Grouped and command-style tool calls** (issue #632, 2026-10-17, supersedes this bullet's earlier "the last call's target plus + N others" grammar): a run of consecutive calls to the same tool collapses to one line reading "`<tool>` ×N" (never any one call's own command or target); the "N failed"/"N interrupted" counts (issue #570, 2026-10-16) AND the group's own total time (the sum of every member's own duration, shown only once every member carries one) join in the row's own never-shrinking meta slot, joined by a visible middle dot plus an sr-only comma -- "N failed" in the error colour the instant any member fails, even mid-run; the header's own icon and label turn red only once the group settles as failed. A `bash` call's own row (solo or nested inside a group) reads `$ <first line of the command>` (a trailing " …" whenever the command has more than one non-empty line); a `grep` call's reads `grep "<pattern>"`, plus the search path when its own arguments carry one as a plain string -- both drop their separate tool-name label entirely (the summary text already names the tool), unlike every other tool. While collapsed the header also shows an **Error line** for the latest failed member, through the same `$ .../grep "..."` grammar, unconditionally prefixed (replaced by each failed member's own line once expanded). Expanding hangs each call, in its own expandable row, from the shared **Spine** (a neutral `border-divider` rule, issue #565) -- the same one the **Stage** group and **Subagent chain** below use, never shown for a group of exactly one call. A thinking line, a different tool, or a pending approval/question ends the run. `ask` calls are never grouped this way; a **Stage**'s subagents group by a separate mechanism instead (see **Subagents** below, issue #563).
- **Hidden bookkeeping tools** (T086, FR-052): the agent's own tool calls for its own bookkeeping (a fixed list, `src/shared/model.ts`'s `HIDDEN_TOOLS`, starting with `todo`) never appear in the chat at all -- the only exception to "every tool call is a row". A hidden call that fails still surfaces, as a plain error notice rather than silently; that notice never splits an otherwise-consecutive run of another tool's calls, or a run of consecutive thoughts (issue #557), apart into two groups.
- **Thinking** (amended issue #557, 2026-10-16: a run of two or more consecutive thoughts, see **Thought run** below): a collapsed "Thinking" line shows a faint one-line preview of the latest text while it streams, and "Thought for Ns" once done; expanding shows the full text through the normal markdown path. A thinking line with no known duration (e.g. one in a reopened Conversation) shows just "Thought", never a guessed number.
- **Thought run** (issue #557): a run of two or more consecutive thinking items with nothing else between them (a hidden bookkeeping tool's own notice does not end it, see above) collapses into one row reading "Thought process" with the step count ("3 steps"), expanding to the individual thoughts, each still its own line as above, down a Spine exactly like a tool group's own members. While any member streams, the header shows the spinner and reads "Thinking" with that live member's own preview, the step count only (no time) -- a live thought is just another member inside; the header itself never becomes a SEPARATE spinning row of its own. Once every member is finished, the header reads "Thought process" with the step count and, when every member carries both timing bounds, the union of their own intervals as the total duration -- never a plain sum, and floored at 1 second so it never reads shorter than any one member -- omitted (step count alone) whenever any member lacks a bound, which is always true for a reopened Conversation. A run of exactly one thought is unchanged: today's own single collapsed line above, with no group header and no Spine.
- **Turn total time**: each turn's activity block ends with a muted line showing the elapsed time ("28s", "1m 14s", "2h 3m"), ticking every second while the turn runs and marked `aria-hidden` until it ends (so a screen reader only reads the final value). Omitted when no item in the turn carries usable timing (a reopened Conversation whose history has none).
- **Question formatting** (issue #491): the live question card and the answered-question expansion both render the question through the shared sanitised-markdown `Markdown` renderer at normal weight, never inside a bold title. A question with more than one line shows its first line as a short heading of medium weight, with the rest as body text with paragraph spacing, scrolling inside a maximum-height region when long so the options and Cancel are never pushed off screen; a single-line question stays one line of normal weight with no separate heading. The heading split is suppressed (whole question renders as body) when the first line starts a markdown block (fence, list item, blockquote, table row, ATX heading, thematic break, setext underline, indented code) or would leave a blank body (gate cycle 3 finding 6). A markdown hard break (two trailing spaces or a trailing backslash) in the body renders one extra blank line, a documented edge case. Options for a choice question stack vertically at full width, each with its label at medium weight and its optional description muted beneath it.
- **Answered questions**: an answered `ask` question collapses to "Asked user:" plus the question cut to one line, expanding to the full question (through the same renderer and heading/body split as the live card above) and its options, with an indented "Answer:" row below carrying a small round avatar of the user's initials, their name (`git config user.name`, falling back to the Windows account name, cached per repository), and the answer ("Cancelled" for a cancelled question). A pending question stays the live approval/question card; a decided approval keeps its own one-line resolved summary.
- **Subagents** (amended issue #563: subagent rows are now grouped, superseding this bullet's earlier "never grouped"; corrected 2026-10-15 quality-gate remediation; gate round 2 architect addendum A corrects the Stage-boundary rule below): the subagents started by one `task()` call (or by `task()` calls issued together within the same owning assistant message, keyed on that message's own id rather than on transcript adjacency) form one **Stage**, rendered as one stable `CollapsedLine` row whose element type never changes as a second agent or a second Stage streams in -- mirroring, never reusing, `ToolGroupRow`'s own "always one wrapper" pattern -- a header (combined status icon, agent count, roll-up, duration with `tabular-nums`) over the member rows, each hung from the shared **Spine** (a neutral `border-divider` rule, never a dot or arrow), still today's own per-subagent collapsed line (status, duration, collapsed by default, expanding to its prompt and, once known, its result as plain text; status word is `sr-only` once finished, since a finished reviewer may still have returned a FAIL). A Stage with exactly one agent always renders identically to that bare per-subagent row, with no group header, regardless of how many Stages the turn has (gate round 2 architect addendum B); only its accessible name states "Stage N of M". A turn with two or more Stages also gets one **Subagent chain** row at the end of the turn, above the turn-total-time line (its own `stage-group`/chain rows share `CollapsedLine`'s baseline bookkeeping rhythm, FR-047): a collapsed summary ("{S} stages, {A} agents" plus non-zero running/failed/cancelled/exited counts) expanding to one line per Stage with that Stage's agents wrapped onto further lines; a turn with exactly one Stage shows only that Stage's own group row in place, no chain row. Activating an agent entry in the **chain** (not a Stage's own member row, which keeps its ordinary expand/collapse) opens it in the **Subagent panel**. No arrows or chevrons on the connector between Stages: it is a timeline of batches, not a dependency graph.
- **Agent-to-agent messages**: an IRC-style message between a subagent and the main agent (or between subagents) is its own collapsed line with a direction icon, "<sender> to <recipient>", and a one-line preview, expanding to the full message; never grouped or hidden.
- **Advisory notes** (T084/T085, FR-051): an OMP-injected `<advisory>` note (one or more per message) becomes its own baseline line, styled by severity -- a blocker in the error colour, a concern in the warning colour, a nit muted -- each also with a distinct icon shape and the severity word, since colour alone is never the cue. The advisor name and a "T-N" turns-ago marker show when present, plus a one-line preview of the note; expanding shows the full note and its guidance as plain text. A note that cannot be parsed shows as a generic notice instead of raw tag text. **Blocker callout** (issue #558, 2026-10-16; gate round 2 amendment): a blocker is expanded by default, live or reopened from history alike, with no focus steal -- the row's own mount into the transcript is itself the one polite announcement (no separate announcer: a gate round 1 attempt at one re-announced on a Session switch and "Load earlier", and still double-read a live arrival, so it was deleted rather than patched again). The expanded body carries a 3px left accent bar (error colour) with no surrounding box, any `path:line`/`path:line:column` location(s) the note or guidance names as monospace copyable text (none shown when none found), the shared icon-only Copy button ("Copy advisory": note, guidance and every location), and an outline "Ask agent to address this blocker" button that composes a message -- the note, guidance and locations inside a fenced code block, bounded against a hostile backtick run or an oversized note -- and sends it through the exact same `chat.send` path a normal user message takes, posted as a real user turn; focus returns to the row's own trigger once the send completes. An expanded concern gets the same accent bar (warning colour) and the same two actions, but only while expanded; a nit gets neither. Every run of consecutive concern-severity advisories in one turn, including a run of one, is always grouped (matching a Tool group or Thought run); a run of five or fewer renders unchanged with no control, six or more collapse behind a "+ Show N more advisor concerns" button placed ABOVE the rows that permanently reveals the rest and moves focus to the first newly revealed row.
- Chat text fills the full width of the transcript column; code blocks, diffs, and tables scroll sideways only when their content is wider.
- **Code blocks** (T083, FR-049/FR-050): every code block -- a fenced block in markdown, and a tool call's Arguments and Output -- shows a small header naming its language, or "text" when none is known or Shiki fails to highlight it; JSON arguments and JSON output are pretty-printed, a tool's diff-shaped output is highlighted as a diff. **Copy button** (#524, Stuart 2026-10-07, PR #597, built: reverses this line's earlier "No copy button (FR-042)"): every code block's header, every edit/PR-change diff (`DiffView.tsx`), and the pasted-text preview (`TextPreviewModal.tsx`) carries an icon-only Copy button that puts the displayed text on the clipboard with control, bidi, deprecated-format and Unicode tag characters removed, unpaired surrogates removed, and a lone CR normalised to LF (`src/renderer/lib/clipboard-sanitise.ts`) -- the full, untruncated value even when a tool's Output or write preview is capped behind "Show all" -- with a "Copied" check state and a polite live-region announcement. **One exception** (issue #558, gate round 3): an "Ask agent to address this blocker/concern" message quotes the advisor's own note inside a dedicated ` ```advisor-note ` fence (never highlighted, since there is no language), which wraps like ordinary prose instead of scrolling sideways -- the note must stay fully readable without a horizontal scrollbar hiding part of a quoted sentence. Every other fence, including a plain untagged one, keeps the rule above unchanged.
- **Every JSON-shaped tool/code surface uses `CodeBlock`** (Stuart, 2026-10-04): the rule above has no exceptions -- a tool call's Arguments and Output, a subagent's Prompt and Result, and a pending approval card's detail lines are all JSON- or code-shaped and all render through the shared `CodeBlock` component (`src/renderer/features/chat/Markdown.tsx`) with language-appropriate highlighting, never as a raw, unformatted `<pre>`/`<div>` paragraph, regardless of which tool or target URI (including an `xd://` device call) produced the content. **A tool call's own Arguments and Output, and a `write` result's content preview, moved out of the row itself and into the "View full call" dialog's Formatted/JSON tabs (#628/#630)**: they still render through this exact same `CodeBlock` component there, unchanged; only a subagent's Prompt/Result and a pending approval card's detail lines still render inline in the row.
- Sending while a turn runs queues a removable chip under the turn. A follow-up chip (still waiting its turn) shows a "Send now" button that promotes it straight to the steering queue (issue #540, PR #598, built, OMP's `promote_queued_message`); a steering chip (already being delivered to the running turn) has no "Send now" button and instead shows a quiet "Sending at the next step" status.
- Approval requests and agent questions appear inline in the transcript at the point they arise, with Approve / Deny or the answer controls, and mark the Session as needs you.
- **Split chat pane** (spec 005): each pane is a complete, independently-scoped chat for its own Session -- header, transcript, message box, queued messages, pending approvals/questions, and the status line -- matching what a single, unsplit pane shows for that Session; a pending approval or question in the unfocused pane stays visible and answerable there without focusing it first. Both panes keep streaming live at the same time; activity in one never delays typing or streaming in the other.
- Agent text, tool output, and file contents are always shown as inert content: never raw HTML,
  never a script-capable surface, never code execution. This does not mean a link is never
  clickable -- a web URL or a worktree file reference (issue #610) still becomes a real
  `<a>`/button, but only through an allow-listed channel (`openExternalSafe`'s http(s)-only
  rule for the system browser; a new `sessions.revealFile` IPC call, resolved only inside the
  Session's own worktree, for "Show in File Explorer" -- never the file's own default-app verb,
  which could execute a `.cmd`/`.ps1`/`.lnk` an agent or tool wrote). Inert means no execution
  and no live markup, not that nothing in the transcript is ever interactive.
- **GitHub-flavoured markdown** (tables, task lists, strikethrough, footnotes) renders on every markdown surface (assistant text, user text, the Thinking row): tables sit in a horizontally-scrolling wrapper with bordered header/data cells; task-list checkboxes are disabled, themed checkboxes; footnotes land in a divided section at the end of the message, numbered and back-linked. Raw HTML in agent/user text never renders (constitution V): it is sanitised away or shown as plain text, never as live markup.
- **Mermaid diagrams** (a ```` ```mermaid ```` fence) render as an inert image, never inline SVG: Mermaid itself (`securityLevel: 'strict'`) is loaded only once the first diagram actually appears, and the rendered SVG is shown as a `data:image/svg+xml` `<img>` -- browsers disable script execution for SVG used as an image, so a diagram cannot run code regardless of what its source contains. A diagram still streaming, over a 50 KB source cap, past a 5 s render timeout, or that fails to parse falls back to the fenced source with a one-line reason above it, never a blank area. Every rendered diagram has a **Show source** toggle and an `aria-label` naming its Mermaid diagram type.
- **Message box** (T063; restyled 2026-10-15, issue #564, refined the same day by a `/grill-with-docs` session, then by gate round 1): a field with a transparent fill and a faint border in Dark and Obsidian, and a full 3:1 border in Dark (high contrast) (amended 2026-10-16, issue #927; see "Composer tone" below) (the field's own focus ring is scoped to the textarea, gate round 5, described at this bullet's end). Send and Stop are round, icon-only buttons (accessible names "Send message"/"Stop", no visible label text) vertically centered on the field's right edge so they stay centered as the textarea grows to multiple lines, rather than pinned to a corner; Send shows a filled up-arrow icon with its OWN `--send`/`--send-foreground` fill (chromatic/indigo in every built-in theme, gate round 1 -- not `--primary`, which is a near-white neutral in Dark and Dark high contrast, nearly identical to Stop there), Stop a filled square icon with a solid NEUTRAL fill (`variant="invert"`, inverted foreground-on-background) -- never red, since stopping keeps the work done so far and is not a destructive action, and red is reserved for destructive and error states (grill decision 5). Each shows its shortcut as key-cap icons (the `Kbd` component) in its tooltip on hover and keyboard focus -- Send: **Enter**, Stop: **Ctrl**+**Shift**+**X**. The field's own bottom row (replacing the old muted provider/model/effort readout line) holds, left to right: the **Approval mode pill** (moved here from the status line above, `ApprovalModePill.tsx`), a **Model picker** and a **Reasoning picker** (each a labelled trigger naming the Session's current value -- the same `lastModel`/`lastThinkingLevel` last-known values the old line read, "Model not known yet"/"Reasoning not known yet" before any value has been seen, or "Reasoning not reported" once a model is known but the agent's last reported state carried no level for a non-Default request, gate round 1), and an **Attach button** that opens a native file picker for images, feeding each chosen file through the same pipeline a pasted image already uses (spec 009). Both pickers refuse to open (showing the last-known value) while the Session is working or needs-you ("Available once the session is idle.") and while it is stopped with no agent running at all ("Start the agent to change the model/reasoning level.", grill decision 3) -- nothing is stored for the next start in the latter case; a picker menu left open closes itself the instant the Session stops being idle or stops running, rather than blocking its own close too (gate round 1 fix). The Reasoning picker lists every one of OMP's levels in order as a radio group, the current one `aria-checked` -- Default (`inherit`), Off, Minimal, Low, Medium, High, Extra high, Max (grill decision 4); requesting Default always shows "Default" once applied, regardless of whether the model echoes the level back, since that is what Default means (gate round 1, amended by Stuart). The Model picker is a popover holding a type-to-filter combobox field with keyboard focus on open (ArrowUp/Down move the active option, Enter applies it, Escape closes the popover) and a listbox below it -- not a native menu, whose own typeahead cannot coexist with a text field (gate round 1 rebuild) -- a **Roles** group first (the Session's roles, `model.listRoles`, applied through the existing `model.applyRole` action), then the filtered catalog list (91 chat models today) with the current one ticked by identity (provider + id, gate round 1), scrolling past about 12 rows (grill decision 6, raised to a 30rem cap gate round 6 once 24rem measured closer to 9 rows). Both pickers target the Rust build only (Electron is being retired, R13, concurrently with this story). While the message box is disabled (the Session is stopped), the unusable parts -- the text field, Send/Stop, both pickers, and Attach -- dim as one `opacity-60` layer; the Approval mode pill stays at FULL opacity throughout, since it still works while stopped, and the box's own border and background never dim either (gate round 4, 2026-10-15). The pill, both pickers and Attach are ghost buttons whose hover adds a faint fill; in Dark and Obsidian they carry no resting border at all, while Dark (high contrast) keeps a real, enforced `--composer-control-border` (`var(--border)`) resting border on each, since that theme's edges stay unchanged (decision 3, amended 2026-10-17, #927 gate). Send and Stop are UNCHANGED by #927 and always keep their own full, opaque `--ring` focus outline in every theme; the pill, both pickers and Attach instead share one muted `--composer-focus` outline in Dark and Obsidian (an exact `--ring` alias in Dark high contrast, so it reads identically to Send/Stop's own outline there) (gate round 5, amended 2026-10-16, #927, corrected 2026-10-17); the box's own focus ring is scoped to the textarea's own `:focus-visible` only, so a focused bottom-row control is never double-outlined.
- **Composer tone** (Stuart, 2026-10-04; **replaced 2026-10-16, issue #927**, grilled from a GitHub Copilot screenshot): in Dark and Obsidian the message box has a transparent fill, so it shows the chat background, and a faint `--composer-border` (around the `--divider` tone); its controls are ghost buttons and its focus outline is muted. Dark (high contrast) keeps a 3:1 border and the full focus ring. Stuart accepted the WCAG 1.4.11 departure this creates in Dark and Obsidian (see "Accepted departures" in [accessibility.md](accessibility.md)). The earlier rule (fill strictly darker than `--background`) no longer applies. The composer still never competes visually with the transcript above it.
- **Ghost-text word completion** (T103, FR-058): while typing a prose word at the end of a line in the message box, a short debounce after the last keystroke shows its likely completion as dimmed, non-selectable inline text right after the cursor -- an overlay, never part of the textarea's own value or selection. Trigger is local-only and never fires mid-word, inside a file-path-shaped token, or inside a slash command. **Tab** accepts the shown suggestion, inserting exactly its text and moving the cursor past it (Tab with nothing shown keeps its normal field-leaving focus movement); **Esc**, typing past it, or any other edit dismisses it. Each shown-then-resolved suggestion reports back to OMP whether it was accepted or abandoned. The request only ever reaches an already-running agent process -- never one that would have to start first -- so typing in a stopped Session's composer never launches its agent (a cold shared prediction daemon's first call can take up to about two minutes). A failed or unavailable prediction degrades silently to no suggestion, never a toast or any other visible error. A screen-reader-only live region (referenced from the field's `aria-describedby`) announces when a suggestion becomes available, without firing on every keystroke.
- **Pasted image attachments** (spec 009, FR-001 to FR-009, FR-018, FR-019): pasting an image into the message box creates a pending thumbnail in a shared attachment strip directly above the box (hidden entirely while nothing is pending) instead of inserting any image data into the textarea's own text; clicking a thumbnail opens the full image in a modal, Esc or an outside click closing it and returning focus to the thumbnail. A pasted image not already PNG/JPEG/GIF/WebP is re-encoded to PNG in the renderer before it ever becomes a pending attachment (Refract never relies on OMP's own fallback); a decoded image over 20 MiB is rejected with an inline toast naming the limit, never shrunk, never sent. Several images may be pending at once, each with its own thumbnail and remove control, independent of each other and of any pending text chip. Sending includes every pending image as a real `images` entry (base64 + mime type) on the `prompt`/`steer` command, clearing the strip once that send is accepted -- not once the agent's turn finishes, so the composer's ordinary sending/working indication carries through OMP's own extra vision-description delay (up to 20 s) without ever looking stalled or showing an error. The main process re-validates every image's mime type and decoded size independently before it is ever sent (constitution Principle V): the renderer's own paste-time check is never trusted alone.
- **Pasted text chips** (spec 009, FR-010 to FR-015): pasting a block of plain text over 800 characters collapses it into a short labelled chip ("first line truncated… (N chars)") right at the position it was pasted, instead of flooding the textarea with the raw block; at or under that threshold a paste still lands exactly as before. The chip's clickable surface renders twice, deliberately: once as a badge in the shared attachment strip (always reachable regardless of the textarea's own scroll position) and once as an inline overlay positioned exactly over the chip's own label text in the draft, reusing the ghost-text overlay's text-metrics technique (T103, FR-058) so it looks and clicks like a chip sitting in place rather than plain text -- both open the same read-only, scrollable text modal. A chip is dropped from pending state the moment its label no longer appears intact in the draft (an edit or an ordinary delete both count), silently and without error; several chips may be pending in one draft at once. Sending substitutes every still-pending chip's full original text back into the plain message string at its own position, independently of the others -- OMP only ever sees the plain string it would have gotten pasting the whole block directly, no new wire capability involved.
