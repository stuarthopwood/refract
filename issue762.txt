Feat: Chat: /switch <model> (alias /model) to change this Session's model, and /models to open the Model roles settings
> **Stuart 2026-10-13:** "Also file `/switch` to change the active Session's model."

This is the keyboard and command-line sibling of #454 (the composer's model picker, **P0**) and shares its RPC call and its probes. It is also the explicit decision the code has been waiting for (see below).

## Current state (read on `origin/main` at `eef3a89`, not run)
- **`/switch` is excluded on purpose.** `src/shared/slash-commands.ts` leaves `switch` out of `SUPPORTED_OMP_COMMANDS` with this reason: its description is "Switch model for this session only", "functionally a model write even though its name does not match the probe's denylist regex... Needs an explicit decision, not silent inclusion" (the T092 probe, `specs/001-core-session-workspace/contracts/omp-usage.md` lines 163 to 168). So today `/switch` is not in the menu and `chat.send` refuses it as `unknown-command`. **This request is that decision.**
- **What the probe did observe:** bare `/switch` completed cleanly and only echoed `Current model: <provider>/<id>`, "read-only without an argument". **No argument form was ever run** (the probe sent each command bare; the whole allow-list policy refuses arguments, `unsupported-arguments`).
- **The RPC call underneath is proven:** `set_model { provider, modelId }` and `set_thinking_level` were exercised live (FINDINGS item 1d, 2026-10): with 67 real models in the catalog, a `set_model` sent **1.5 s into a streaming turn** returned `success` with the new `Model` and a later `get_state` showed it applied. That confirms OMP accepts it mid-turn; it does **not** say what happens to the in-flight turn (still unprobed, and #454 and #740 carry the same question).
- Refract never sends `set_model` today (`grep` of `src/main` and `src/shared` finds none) and has no model picker; the composer strip is read-only (#454).
- `/effort` **is** already supported (levels `off` to `max`, `auto`), so the thinking level already has a command; `/switch` completes the pair for the model.

## Proposal (mine, for Stuart to change)
**Behaviour**
- **`/switch` alone:** shows the current model as a notice row, as the probe observed ("Current model: Claude Sonnet 5.5", with the provider per #741's display rule).
- **`/switch <model>`:** changes **this Session's** model only, nothing written to the global config, no role change (OMP's own description: "for this session only"). On success the composer strip's model label updates (Refract re-reads `get_state`, the existing `syncFromState` path) and a notice row says "Model switched to X". A thinking level the new model cannot use is clamped by OMP; the strip shows what OMP applied.
- **Argument:** one model token. Accepts `provider/id` and, if OMP resolves it (**probe**), a bare id, a partial name, an alias such as `@smol` or a thinking suffix `:high`. Ambiguous, unknown or "not signed in for that provider" results come back as OMP's own message, shown as an error notice, with the model unchanged.
- **Autocomplete after `/switch `:** the slash menu lists the models from `get_available_models` (already filtered to what the user is signed in for), grouped by provider, filtered as you type, showing the **friendly name** (provider stripped, #741), with the **current model marked** in text. Enter inserts the full `provider/id`. The menu works from the keyboard like the rest of the slash menu. The menu lists one entry, **`/switch` with the alias `model` shown beside it**, not two commands.
- **While the Session is working:** open decision, recommendation first: **refuse with a clear message** ("Switch the model after the current turn") exactly like `/new` does with `SessionNotIdleError`, because the probe proves OMP accepts it mid-turn but not what the running turn does. The alternative is to queue it for the settle. Mid-turn switching can be enabled later if the probe shows the in-flight turn is unaffected.
- **Pinning (shared rule with #454 and #740):** a model chosen with `/switch` **pins** the Session, so a later role change in Settings (#740) does not move it.

**Implementation shape (policy, constitution I)**
- `/switch` is an OMP command present over RPC, so Refract **forwards** it to OMP rather than reimplementing it (constitution I: native only what RPC lacks). Alternative: call `set_model` directly with the picked model; the probe decides which is more robust (a command string needs OMP's argument parsing, the RPC call needs `provider` and `modelId` separately). Either way the user-visible command is `/switch`.
- Add `switch` to `SUPPORTED_OMP_COMMANDS` with **one new verified shape: a single model-token argument** (charset-checked: letters, digits and `._:/@-`, no whitespace), the first command allowed an argument; `classifySlashInvocation` must treat that exact shape as supported while every other argument stays `unsupported-arguments`. Update the header comment and `omp-usage.md` line 163 (the "deliberately excluded" note) and `FR-032`'s exclusion list. This composes with #760: built-ins stay allow-listed per verified shape, user-authored commands do not.
- Reserved names stay refused (`/plan`, `/new` and the rest).
- **`/model` is an alias of `/switch` (Stuart 2026-10-13).** Typing `/model` or `/model <model>` in Refract behaves **exactly** as `/switch` and "/switch" lists `model` in its `aliases` so the menu shows both names. **It must never reach OMP as `/model`:** OMP's own `model` command (alias `models`) opens the model hub and **writes role assignments**, which T092 flagged as a model write ("/model writes") and which is what the Settings Models page (#455) is for. So the alias is a **Refract-side rewrite in `chat.ts`, before anything is forwarded**: the parsed name `model` is mapped to `switch` and the rewritten text is what OMP receives; OMP's own `model` entry in `available_commands_update` is dropped from the menu (it is not on the allow-list, so `filterSupportedCommands` already hides it) and `model` joins `NATIVE_RESERVED_COMMANDS`-style handling so a later OMP change, or a user command named `model` (#760), can never take the name over. Bare `/model` therefore prints the current model (the read-only form the probe saw for `/switch`) instead of opening the hub.
- **`/models` opens the Settings role page (Stuart 2026-10-13).** It is **not** forwarded to OMP (OMP's `models` is an alias of its hub, which writes role assignments) and it is **not** an alias of `/switch`: it is a Refract-native command that navigates to **Settings, Model roles** (the `model-roles` section, #455), the place role assignments are edited. Handled in the renderer exactly like `/btw` is today (`MessageInput.tsx` `handleSend` recognises the parsed name before `chat.send`): clear the draft, call `useViewStore.openSettings('model-roles')` (already exists, `view-store.ts` line 45), send nothing. The Settings back button returns to the chat; the composer draft survives (spec 010) and focus returns as for any Settings visit. `models` joins the reserved names so `chat.send` refuses it with `unknown-command` if it ever arrives (defence in depth) and a custom command (#760) cannot take it. In the menu: `/models`, "Open model role settings". After #714 renames or regroups the section the command opens that page (it targets the section id, not a label). With a split chat, it opens Settings for the window as any Settings entry does. Pair this with #8 (native `/settings`, listed but unbuilt in `NATIVE_RESERVED_COMMANDS`): the same mechanism, so build both together if convenient.

## Accessibility (WCAG 2.1 AA)
The menu keeps its listbox semantics; each model option's accessible name is the friendly name plus "current" where it applies and the provider as a description; the result is a notice row announced politely once ("Model switched to Claude Sonnet 5.5"), an error is announced assertively as for other refused commands; no colour-only state.

## Acceptance
- Probe results recorded here.
- `/switch` appears in the slash menu; bare it prints the current model; `/switch <valid model>` on an idle Session changes it, the composer strip and Session card update, the next turn is served by the new model (confirmed in the Session file), and nothing is written to the global role config.
- `/switch` with an unknown, ambiguous or unavailable model leaves the model unchanged and shows OMP's message.
- On a working Session the command follows the decision above (refused with a clear message, or queued) and never corrupts the running turn.
- `/switch` cannot be given a second argument or a flag; every other command keeps today's argument refusal.
- `/models` in the composer opens Settings on the Model roles page, sends nothing to OMP (a test asserts no `chat.send` reaches OMP), clears the draft, and Back returns to the same chat with its draft; `/models` never opens OMP's hub.
- `/model` and `/model <model>` behave exactly like `/switch` and `/switch <model>`; a test proves the text sent to OMP is `/switch ...` and **never** `/model ...` (the hub, which writes role assignments, is never opened from the composer); a custom command named `model` cannot take the name.
- A Session switched with `/switch` is not moved by a later role change (#740).
- Typecheck, unit tests for the argument shape rule (one token accepted, empty, two tokens, path-like, flag-like, over-long) and the classification, and a live check on a scratch instance.
