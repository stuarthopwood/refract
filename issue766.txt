Feat: Chat: role switcher: /role, /role <role>, and a Ctrl+R selector that cycles OMP's roles and plan (applied on Ctrl release); /plan composes with plan mode
> **Stuart 2026-10-13:** "`/role` allows the user to change the current role. `/plan` enables plan mode and switches to the plan role. `/role <role>` is supported. `Ctrl+R` cycles between roles with a visual selector that highlights the selected role in sequence for each role."
>
> **Decided by Stuart (question tool, 2026-10-13):** the new role is **applied when Ctrl is released** (Alt-Tab style, Esc cancels); Ctrl+R cycles **OMP's `cycleOrder` roles plus `plan`**.

This is the **role switcher** that #714 part 4 (role colours), #717 (role icons) and #741 (current role in the composer) were prepared for. It is the third way to change what a Session runs on: #454 (composer picker) and #762 (`/switch`, `/model`) pick **a model** and pin the Session; this puts a Session **on a role**, so it then follows that role's model when the role changes in Settings (#740).

## Current state (read on `origin/main` at `bc94fc0` and in the installed OMP docs, not run)
- **Refract has no role switcher and never changes a Session's model** (no `set_model` or `cycle_model` anywhere in `src/main` or `src/shared`). The composer strip shows the model and effort read-only (`MessageInput.tsx` about 1386 to 1404).
- **OMP cycles roles itself.** Its keybinding `app.model.cycleForward` (Ctrl+P) "cycles role models forward" and `Shift+Ctrl+P` backward over the `cycleOrder` setting (default `["smol","default","slow"]`; custom roles can be added through `modelRoles`, `modelTags` or `cycleOrder`) (`omp://keybindings.md`, `omp://settings.md`). Over RPC there is a `cycle_model` command; its response shape, and whether it has a backward form, are not documented here (probe).
- **No RPC command sets "the role".** `set_model { provider, modelId }` takes a model, not a role. The role of the Session's current model lives in the Session file (each `model_change` entry has a `role`, `omp://session.md`), and `get_state` carries no role (#741). Whether `set_model`, `cycle_model` or OMP's `/switch <arg>` record a role is the probe both #741 and #762 already need.
- **Plan mode:** OMP has it (`Alt+Shift+P` toggle, a `mode: plan` entry with a `planFilePath`, subagents read-only while it is on) and "while plan mode is active, changing the `plan` role reapplies its model" (`omp://models.md`). It is **absent over RPC** per the repository's own findings (FINDINGS item 1; constitution I lists `/plan` among the commands Refract supplies natively) and `plan` is reserved but unbuilt (`NATIVE_RESERVED_COMMANDS`). #433 holds the open question "can rpc-ui enter and leave plan mode?".
- **Ctrl+R is free in production.** The only binding is the development build's View menu `role: 'reload'` (`src/main/menu.ts` about line 27, `CmdOrCtrl+R` in dev only). The transcript, composer and Settings have no Ctrl+R handler (`grep` of `src`).

## What to build
**1. `/role` and `/role <role>`** (a Refract-native command, handled like `/btw` and `/models`; the name is reserved).
- `/role` alone opens the **role selector** (below) anchored above the composer; `/role <role>` switches directly. The argument is one token validated against the role list (`cycleOrder`, `plan`, and the other chat roles known from `modelRoles`); an unknown name is refused with the list of valid ones, nothing changes.
- The slash menu completes role names after `/role `: each option shows the role's **icon and name, the model it currently resolves to (friendly name, provider stripped, #741), and "current"** in text where it applies. Roles with no assignment show what they inherit, **only where the #714 probe has confirmed the chain**.
- Switching puts the Session **on that role**: it follows the role if Settings changes it later (#740); a model chosen by `/switch` or the picker **pins** it, and choosing a role again un-pins.
**2. `Ctrl+R` role selector** (decided).
- **Ctrl+R opens the selector and highlights the next role** in the cycle; **each further Ctrl+R moves the highlight one role forward**, wrapping; **Shift+Ctrl+R moves backward**. **Releasing Ctrl applies the highlighted role**, **Esc cancels** (the Session is unchanged), Enter applies at once. One model change per use, no intermediate models flicker through.
- **The selector** is a floating layer (elevated surface, shared shadow token) centred just above the composer: a horizontal row of **role chips**, in cycle order, each with the role icon (#717), the role name as text and the model it would use; the **current** role carries a text tag "current"; the **highlighted** role has a strong outline and heavier weight plus the role colour (#714 part 4) as a second cue, **never colour alone**. The model line updates as the highlight moves, so you see what you are about to get. Fade in 100 ms, none under reduced motion.
- **The same selector** opens from `/role` bare, and from a **click on the role chip** in the composer strip (#741), where pointer, arrow keys (Left, Right, Home, End), Enter and Esc work without holding Ctrl. This is also the **non-chord route**: holding Ctrl and tapping is awkward for some users, so every function is reachable without it (`/role` or the chip).
- **Scope of the shortcut:** only while keyboard focus is in a chat pane (transcript or composer); in a split, it acts on the **focused pane's** Session (#684); not while a Settings field, dialog or the Explorer has focus.
**3. `/plan`** (composes with #433): `/plan` **switches to the `plan` role and enters plan mode**. The role half is this issue; the plan-mode half **depends on #433's spike** (can an rpc-ui host enter and leave plan mode, and how does the plan proposal and its approval arrive?). **Until the spike answers, `/plan` stays refused as today**: it must not ship as a role switch that claims to be plan mode. If RPC cannot do it, the native route is a bundled Refract extension (the way `/btw` uses `runEphemeralTurn`, FINDINGS item 1), decided in #433. **Leaving plan mode** (proposal, mine): `/plan off` leaves plan mode and returns to the role the Session was on before (remembered for the run); switching role with `/role` or Ctrl+R does **not** by itself leave plan mode (OMP treats them as two things); the approval of a plan ends plan mode as OMP does.
**4. Rules shared with #762:** a role switch is **refused while the Session is working** ("Switch roles after the current turn", a toast, the same message style as `/new` and `/switch`), because OMP accepts a mid-turn model change but what the running turn does is unprobed; a failed switch (model unavailable, not signed in) leaves the role unchanged and shows the error on that Session.
**5. Dev builds:** move the development reload off Ctrl+R (for example F5) so the shortcut works while developing.

## How the role is applied (probe-gated, in order of preference)
1. **OMP resolves it:** `cycle_model` for a step in `cycleOrder`; for a direct jump (`/role slow`, `plan`, backward) OMP's own `/switch @<role>` if OMP accepts a role alias there (models.md: "role aliases like `@smol` expand through `settings.modelRoles`") **and** records the role. Constitution I prefers this: Refract does not reimplement role resolution.
2. **Otherwise Refract resolves the role's selector** (read `modelRoles` and `cycleOrder` with `omp config get`, expand aliases, thinking suffix, candidate lists, project override) and calls `set_model`, then records the role itself in a minimal Session field so the chip and #740 know the Session is on that role. This duplicates part of OMP's resolver and the project-override question (#455's "still controls" note), so only if 1 is impossible.

## Probes first (one throwaway script, scratch profile, OMP 18.10.1; shared with #454, #740, #741, #762)
1. `cycle_model`: response shape, does it return the role and model, what does it write to the Session file (`model_change` role), is there a backward form, which roles does it visit (just `cycleOrder`)?
2. `/switch @slow`, `/switch slow` and `set_model` with a role-resolved model: accepted? what role is recorded? does a resume restore the role?
3. Can Refract read `cycleOrder` and the effective `modelRoles` for a Session's cwd (project override) with `omp config get`?
4. Plan mode over RPC (shared with #433): enter, leave, what frames, what model is applied on entering.
5. Behaviour while a turn streams (shared with #762): run, queue or refuse?
Record the answers on this issue before any code.

## Spec
A new short spec through Spec Kit (role selector, Ctrl+R chord, `/role`, `/plan` composition) with a **UX consult on the selector** before build (a chord-held selector is a new interaction in this app). Amends the spec 001 slash command rules (FR-032 and FR-033, as #760 and #762 do) and uses spec 004's readout chip area.

## Accessibility (WCAG 2.1 AA)
- The selector is a `listbox` (or `radiogroup`) of options with an accessible name ("Role"), the highlighted option announced politely on each move ("Slow, Claude Opus 5, 3 of 4"), the applied role announced once on release, a cancel announced once; focus returns to where it was.
- **Hold-and-tap is not the only route**: `/role`, the chip click, and Settings cover the same function without a chord (2.1.1).
- Role colours meet 3:1 against the selector surface, and the highlight is outline plus weight plus text, never colour alone (1.4.1); High contrast keeps the outline thicker; reduced motion removes the fade.
- The shortcut is documented in tooltips and the menu bar's help entry; Ctrl+R is a modified key so single-key shortcut rules (2.1.4) do not apply; it never fires in text fields outside the chat pane.

## Acceptance
- Probe results recorded here.
- Ctrl+R in the composer shows the selector with the next role highlighted; each further press moves the highlight, wrapping; Shift+Ctrl+R goes backward; releasing Ctrl applies the role, Esc cancels with no change; the composer strip's role chip and model update to what OMP applied.
- `/role` opens the same selector; `/role slow` switches directly; an unknown role is refused with the valid list; the roles in the menu show icon, name, model and "current".
- A Session on a role follows that role when Settings changes it (#740); a Session pinned by `/switch` is un-pinned by choosing a role.
- While the Session is working the switch is refused with a clear message and nothing changes.
- `/plan` stays refused until #433's spike lands; then it switches to the plan role and enters plan mode, and `/plan off` returns to the previous role.
- Dev builds no longer reload on Ctrl+R.
- Typecheck, `check:ui-text`, `check:theme-contrast`, unit tests for the cycle order (cycleOrder plus plan, wrap, backward, single role), the chord state machine (open, advance, release, Esc, focus loss cancels), and the `/role` argument validation; a live check on a scratch instance with screenshots on Dark and High contrast.
