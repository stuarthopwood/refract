# Product layout

Decided by Stuart in the #474 grill, 2026-10-08.

This page covers the three-region window layout, panes, the session list, the Approval mode pill, the merged title bar, and the profile item -- the product-level shell of Refract.

## Layout


- Three regions: **session list** (left), **chat** (centre), and a right region for Subagents and (later) changes/files/side chat. Spec 004 gives it its first occupant: collapsed to zero width (`collapsedSize={0}`, permanently mounted rather than conditionally rendered, so `react-resizable-panels` never recomputes sibling widths on open/close) until the **Subagents** chip opens the **Subagent panel**; closing it collapses the pane back to zero width and leaves the chat pane's own size and scroll exactly as they were (pixel-measured, not by eye).
- **Split chat pane** (spec 005 FR-001 to FR-023): the centre region shows one **Chat pane** (a full Session's chat) or two, side by side, separated by a draggable **Divider** (a `react-resizable-panels` `ResizableHandle`, keyboard-operable, position persisted via `Settings.split`); **Open in split** (a session row's menu item, or Ctrl+click the row) turns one pane into two. Exactly one pane is **Focused** at a time -- a left-edge accent bar plus a visible "Focused" text badge on its header, never colour alone -- and it is the one every session-row click, the message box, Stop, the queue, and approvals act on; clicking or typing inside a pane focuses it, and **Ctrl+Shift+\** (or a small focus-move button on the divider handle) moves focus to the other pane without the pointer. Each pane has its own close control (`[A, B] -> [survivor]`, full width); a single pane's close control (or Ctrl+W, #621) returns `[A] -> []`, the "Select a Session or create one." empty state; choosing a session already shown elsewhere focuses that pane instead of duplicating it (the same session is never shown in both panes at once). Below `2 × 360px` of chat-area width the pane collapse to one (the focused Session), with a small chip in its header naming the other (hidden) Session that swaps to it in one click, re-splitting automatically once the window is wide enough again. A split survives a restart (both Sessions, the divider position, and the focused pane restored, FR-014) without starting either agent -- each restored pane looks exactly like a never-opened Session until the developer actually opens it (sending a message, clicking its row, or choosing Open in split on it); a Session dropped from a restored split (deleted or archived) leaves the other at full width.
- The **Approval mode** pill (`ApprovalModePill.tsx`) sits inside the message box's own bottom row (2026-10-15, issue #564; moved out of the status line above the box, where it used to sit first): the current mode's lucide icon and name, opening a square-cornered `DropdownMenu` of all three modes (Ask/Edit freely/Auto, each with its icon, name, and a one-line description of what it prompts for), the current one marked by a check icon and the word "Current"; a mode change waiting for the session to go idle shows on the pill itself ("Auto after this turn"); both the pill and its menu are fully keyboard-operable, and the pill's accessible name states the current mode.
- A **status bar** along the bottom carries the low-memory warning and (once spec 006 ships it) the update badge; the Approval mode switch that used to live here moved to the pill, now inside the message box (spec 001 T098, relocated again 2026-10-15 by issue #564). The status bar itself is not yet removed -- that is spec 001 T099, which waits on spec 008's profile item to exist first (its own foundational phases are substantial, not a quick slice); until T099 lands the status bar keeps running along the bottom exactly as before, just without its Approval mode control.
- The **title bar is merged into the app's own top row** (spec 001 T100): the window has no native frame or menu bar at all. The left nav's header (the Refract icon and its name) starts at the very top of the window, and the chat header sits beside it; together they form the app's top row, draggable to move the window (every button, input, and menu inside them stays clickable), with a double-click on the draggable area maximising or restoring the window, and the top-right of the row always reserved for the window's own minimise/maximise/close buttons, painted in the active theme's colours (dark only today). The native menu does not reveal while Alt is held once the title bar is merged this way -- confirmed live against a real interactive desktop with a working framed-window baseline in the same run, not assumed (`docs/spike/FINDINGS.md` item 33, correcting the earlier inconclusive item 24) -- so Refract draws its own File/Edit/View/Window menu bar instead: a standalone Alt tap shows it (never a combo like Alt+Tab), Esc or a click away hides it, and every item opens the real native Tauri popup menu (`src-tauri/src/shell/menu.rs`'s `popup_menu_at`), so copy, paste, undo, redo, and zoom all keep working through that menu whether the renderer's own bar is shown or not.
- Panes resize by dragging their borders; the session list can be hidden -- its panel collapses to zero width but its content stays mounted, marked `inert` and `aria-hidden` rather than unmounted, so the Sessions nav's own open groups, scroll position, and any in-progress rename survive being hidden and shown again; focus-fallback helpers (`src/renderer/lib/focus.ts`) treat a stale `inert` ancestor the same as absence from the DOM.
- Session list: collapsible group per **Project**, **Sessions** sorted by most recent activity, each a 44px two-line row (issue #567 decision 8): line 1 is the state icon, the truncating title (its weight never changes when selected, decision 3), and the relative time at the right (issue #731: **Unread response** is drawn by the state icon alone, no separate dot); line 2 is one slot, first match wins -- start-progress text, "Terminated unexpectedly", an archived row's own Project name, otherwise the branch in the Code font (decision 9). The time hides and the row's own `⋮` menu button takes its place on hover, focus inside the row, or an open menu, both shown together under a touch pointer (decision 12). Hovering a row's open button, or giving it keyboard focus, opens a **details card** after about 750 ms (stays open while the pointer is over the card, dismissed by Esc, never covers the row, suppressed while that row is renaming): the state icon and status label, the relative last-activity time, the project (folder icon), the branch (with the Base branch as muted "from <base>"), the worktree's absolute path (wraps, muted, marked "(missing)" instead of showing a stale one when the worktree is gone), the files-changed count from `sessions.diffStat` ("Counting changes…" while it loads, then "N files changed +A -D", or "partial" past the 200-file/1 MiB-per-file cap, or muted "Not available" when the worktree is missing or the count could not be computed), and **Copy path**/**Open in file explorer** buttons (`sessions.revealWorktree`); the same two actions are mirrored on the row's `⋮` menu since Radix hover cards are not keyboard-reachable. The provider/model/reasoning-effort readout (T062's `lastModel`/`lastThinkingLevel`, "Model not known yet" when absent) sits between the worktree path and the files-changed count. **Archived** Sessions (issue #527) sit in one collapsed, cross-project group at the very bottom of the list -- not sub-grouped by project -- built from a shared `GroupHeaderTrigger` component so its header (chevron, size, case, padding) can never drift from a Project header's own again; its own label reads "Archived" followed by a separate `tabular-nums` count, never `Archived (N)` in brackets (issue #567 decision 5); each row additionally shows its own project name on line 2 in place of the branch, since it no longer sits under one. Hidden entirely when no Session anywhere is archived; restoring a Session moves focus to its own row once it reappears under its Project. **Group header icons** (issue #528): every header -- a Project's and the Archived group's -- leads with an `aria-hidden` icon (`FolderGitIcon`/`FolderGit2Icon`/`ArchiveIcon`, all `lucide`), distinguishing a project with a configured git remote from one that is local only (a repository detection reader could not confirm either way never claims local-only); the icon's own meaning is a Radix tooltip on hover/focus and is appended to the header's accessible name ("PINION, Git repository, remote: github.com"), never colour alone; labels are sentence case, never uppercase or letter-spaced (issue #567 decision 4). Each Project header has three actions, ghost `icon-xs` (24px) buttons hidden at rest and revealed by opacity on hover/focus anywhere in the header/this control's own open menu/a Session being created/an empty group, always shown under a touch pointer (issue #567 decision 6): **+** creates a Session from the default branch in one click (tooltip "New session from <default branch>"), the branch icon opens the Base branch picker with the default branch preselected (tooltip "New session from a branch…"), and **⋮** opens the project's own actions menu; either of the first two ways the new Session is selected and opened. The picker opens below its field and lists two groups: **Branches** (default first) and **Sessions** (each Session's display name, its branch id, and an **Archived** tag for archived Sessions). Right-clicking a row's card opens the same options menu as its `⋮` trigger (a shared `ContextMenu`, never a second menu to keep in sync).
- **Collapse all / Expand all toolbar** (issue #735): a pinned row above the session list's scroll area, below Pull requests, with two icon-only ghost buttons in fixed order (Collapse all, Expand all), each `aria-disabled` with a reason tooltip when it would be a no-op. Each Repository group's own open/closed state, and the Archived group's own flag, persist in `Settings.sessionListCollapse` and survive an app restart (replacing the session list's own previous uncontrolled, always-re-expanding `Collapsible defaultOpen`/always-closed Archived group); a Repository removed from Refract is pruned from the saved state. A closed group whose Sessions include one needing the developer, one that terminated unexpectedly, or one with an unread response (#731) shows a single Waiting marker naming the most urgent of the three; the Repository group currently holding the visible Session shows a 2px active-indicator bar on its header while closed. A closed group reopens, and that open is saved, only when a create or a restore from Archived moves a Session into it.
- Chat header: Session name and branch, and a Conversation switcher (history of that Session's Conversations); the pending-Approval-mode chip that used to live here moved to the Approval mode pill, now inside the message box (spec 001 T098, relocated again 2026-10-15 by issue #564). The header is also the right half of the app's merged top row (see above).
- **Status line** (spec 004 FR-001 to FR-010, FR-021, FR-023; renamed from "Session readout chip row", 2026-10-15, issue #564, when the Approval mode pill moved out of it and into the message box): spans the chat column's full width, between the transcript and the message box. Every entry (a **Readout**) is read via `ReadoutChip.tsx`'s shared baseline, plain text with no border or fill -- a read-only one is an icon plus text; one that opens something (Pull request, Subagents) is a quiet text control with a hover background, still no border (2026-10-15 grill, decision 1). Which show is chosen per-kind in Settings (below), live for every open Session, hidden entirely or reading "Not available" per its own rule, and the line wraps onto a further line rather than hiding a readout or overlapping the message box once the window narrows; the Current time readout, when enabled, sits last at the line's right end. **Changes**: "N files, +A -D", each figure abbreviated past 1,000 by one shared lower-case k/m/b formatter (issue #437, 2026-10-15 grill: at most one decimal, trailing zero dropped, round half up, English suffixes regardless of locale), or "Not available" when the worktree or Base branch is missing -- matches the session list's own details-card figure, which uses the same formatter so the hover card and the status line never show a count two different ways. **Context window usage**: "N/M (P%)" with that same k/m/b formatter and no literal word "tokens" (for example "44.8k/1m (4%)"), hidden when the agent never reports it at all, "Not available" when a reading was expected and never arrived, and a visible warning (a triangle-alert icon plus the literal word "high", never colour alone) once usage reaches 90%; the full wording ("Context usage: 44.8k of 1m tokens used, 4 percent", including the high state) reaches assistive technology through a real `sr-only` phrase next to the `aria-hidden` visual text, the same pattern the Current time readout already uses (a role-less `<span>`'s `aria-label` is ignored by several real screen readers, issue #437). **Turn time**: ticks once a second while a turn runs ("28s", "1m 14s"), hidden otherwise. **Current time**: a pure client clock updating at the top of each minute, off by default, with no `aria-live` region (so the routine tick is never announced) and a static accessible name read only on focus. **Pull request**: "#N" for the Session's branch's open pull request on GitHub (`gh pr list`, no stored token), hidden when there is none, no remote, or `gh` is unavailable, with no error toast either way; activating it is a real external link (`target="_blank"`, the same `setWindowOpenHandler`-to-`shell.openExternal` path `Markdown.tsx` already uses for links in agent text, not a new IPC call) opening the real pull request in the system browser, accessible name "Open pull request #N". **Subagents**: the current turn's running-or-finished count (failed excluded), hidden before a turn has started any, activating it opens the Subagent panel below. **Todo progress**: "Todo N/M" from the agent's own task list, hidden when it has none.
- **Settings screen** (spec 004 FR-011 to FR-016): reached via the profile item's cog (spec 008 FR-002, below) replaces the session-list-plus-chat view with a left-section-list layout; two sections today, **Session readout** (all seven readout kinds above with their own on/off switch, each applied live) and **Appearance** (spec 007's theme picker, live preview, Save/Cancel). A **Back to chat** icon button returns to the session list and chat.
- **Profile item** (spec 008 FR-001 to FR-007, FR-018 to FR-024, `ProfileItem.tsx`/`ProfileMenu.tsx`; UI review, Stuart 2026-10-05, ui-architect-v3; post-build review fixes, Stuart 2026-10-05): pinned at the bottom of the session list, below its scrollable area -- the active GitHub account's round avatar and display name (a shared `initials` fallback, `src/renderer/lib/initials.ts`, while the avatar is loading, failed, or unset), and a separate **cog** button beside it. The name button is 40px tall and the cog 32px, filling the full 48px bar with no dead click band above or below either. Five sign-in states, each icon plus text, never colour alone, and each with an accessible name that starts with its own visible text (WCAG 2.5.3): **loading** (disabled while the first account read is in flight, name "Checking GitHub sign-in"); **signed in** (the account's avatar and display name, `@login on <host>` as the name tooltip); **GitHub CLI missing** (a "?" avatar fallback, name "GitHub CLI missing", FR-014); **GitHub unavailable** (a `gh-failed`/thrown-invoke read with nothing cached -- an amber triangle avatar fallback, name "GitHub unavailable", reachable only through the profile menu's own "Check again"); and **needs attention** (the active account's own GitHub sign-in problem, `state !== 'success'` -- an amber triangle icon beside the name, the accessible name appending "{name}, GitHub sign-in needs attention" for an expired/other credential problem or "{name}, can't reach GitHub" for an unreachable host, `account.problem === 'unreachable'`). Selecting the avatar/name part anywhere opens the **profile menu** (a `DropdownMenu`, `w-64`, `max-h-(--radix-dropdown-menu-content-available-height)` with its own scroll, so a very short window scrolls the menu instead of flipping or shifting it) upward (`side="top"`, 6px offset), items depending on GitHub sign-in state. Signed in: a two-line identity card (display name, then `@login on <host>`, or -- when the active account's own sign-in needs attention -- the same warning icon next to the name and "GitHub sign-in needs attention"/"Can't reach GitHub" in place of the host line); when it needs attention, a conditional **Fix sign-in…** (or, for an unreachable host, **Check GitHub connection…**) item follows immediately, opening Manage accounts and focusing the active row's own recovery button (Sign in again, or Check again) without starting any sign-in itself; then a separator; **Manage accounts** (`UsersIcon`); **Manage sessions** (`LayersIcon`), opening the dedicated cross-repository sessions screen (below); a separator; a **Theme** submenu (`PaletteIcon`) listing every built-in preset from `THEMES` with the exact same data-driven swatch `ThemePicker.tsx` already uses (each theme's own real background colour, never a hard-coded hex, `size-4` to match the Appearance settings icon), the active one marked by a trailing check icon plus the word "Current" -- the ONLY current-theme marker (gate round 7 fix, `agent://Arch877`: the permanent 2px `--active-indicator` bar this row used to ALSO draw is gone, since gate round 5 made that same bar every dropdown menu's own keyboard-focus cue -- "Decided (Skippy, delegated by Stuart 2026-10-15)": in a dropdown menu specifically, the bar means focus only; see "Active/selected indicator" in [product-look-and-feel.md](product-look-and-feel.md), which still covers every other current/selected surface unchanged); opening the submenu by keyboard moves focus straight to the active preset (a controlled `open`/`onOpenChange` plus a ref, checked only when focus is already inside the submenu, so a pointer-hover open is left alone) -- Radix's own default of focusing the first item only looked right while "Dark" (the first preset) was also current. Choosing a different one applies and persists at once through `useThemeStore`'s `save` (a menu is a transient overlay -- live preview with Save/Cancel stays Settings' Appearance section's job alone; a save that throws is caught and toasted the same way, never left unhandled), then a separator and **Appearance settings…** opening that section (which unmounts ProfileItem entirely, so focus goes to Settings' own first control, not back to the name button); **Keyboard shortcuts** (`KeyboardIcon`); an **update entry** (issue #569, spec 008 FR-021 amended 2026-10-16, T024b, `RefreshCwIcon`) reading "Restart to update" plus a plain trailing version (a leading sr-only space, " version ", so the accessible name always has a word boundary regardless of flex layout) once a download is waiting for the next quit (selecting it only confirms with a toast, never quits or installs itself); otherwise the busy phases (checking/downloading/installing) each show their own visible verb -- "Checking for updates…", "Downloading update…", "Installing update…" -- `aria-disabled`, no separate `aria-label` (the visible text already starts the accessible name); any other phase (idle, available, failed, or GitHub-CLI-unavailable) reads plain "Check for updates", selecting it re-checks and shows one outcome toast (an explicit "available" branch names the version; the unavailable-reason and up-to-date outcomes are `toast.info`, never `toast.error`, which is reserved for a real failure) -- never the status bar's own fuller idle/checking/available/downloading/failed/unavailable detail, which stays `StatusBar.tsx`'s alone; **Health check** (`ActivityIcon`); **What's new** (`SparklesIcon`, trailing `ExternalLinkIcon`); a separator; then a destructive **Sign out** item for the active account. Signed out: an enabled **Sign in to GitHub…** item (`LogInIcon`) that opens Manage accounts AND starts the add-account flow immediately (there is nowhere else signed-out to show the flow's one-time code), **Manage accounts**, **Manage sessions**, a separator, then the same Theme/Keyboard shortcuts/Health check/What's new group (no Sign out, nothing is signed in). GitHub CLI not installed: an **Install GitHub CLI** link item (leading `DownloadIcon`, trailing `ExternalLinkIcon`, matching What's new's own icon placement), **Manage accounts**, **Manage sessions**, a separator, then that same group. GitHub unavailable (a `gh-failed`/thrown-invoke read): a "GitHub unavailable" item in Sign in's place (amber triangle, or a spinner plus "Checking…" while a refresh already runs), its trailing text reading "Check again", selecting it re-reads every account; then the same Manage accounts/Manage sessions/Theme/Keyboard shortcuts/Health check/What's new group. GitHub sign-in status still loading: a disabled **Checking GitHub sign-in…** item (`LoaderCircleIcon`, spinning) in Sign in's place, then the same group -- so a slow or hung `gh` call never hides Health check, the one diagnostic tool that could explain why. **Manage sessions** never depends on GitHub sign-in state, so it appears identically in every variant, and this shared block (Manage accounts through What's new) renders exactly once regardless of branch, so a `githubStatus` change while the menu is open can never remount it and drop focus. Arrow keys navigate the menu, including into and out of the Theme submenu; Esc closes it; focus returns to the profile item's name button on close. Every dialog the menu opens (Manage accounts, Sign out, **Keyboard shortcuts**, **Health check**) is mounted as a sibling of the `DropdownMenu`, each with its own explicit `onCloseAutoFocus` returning focus to that same name button -- none is given a `Trigger`, so Radix's own default close-auto-focus would otherwise drop focus to `<body>` (confirmed live, not assumed). Choosing a theme announces "Applied theme {name}", and a completed Sign out announces "Signed out {name}", through the one shared polite live region mounted here. Selecting the cog instead opens the Settings screen directly, without opening the menu; its tooltip names the Settings action, suppressed while the menu is open so the name tooltip and the menu never stack on the same trigger. Opening the menu no longer re-reads the account list itself (removed: unmounting the focused first row while a non-modal menu was open could drop focus to `<body>`) -- the list instead refreshes when Manage accounts opens, and whenever the window regains focus or the tab becomes visible again, throttled to once per 5 s and skipped entirely while a read is already in flight or an add-account/sign-in-again flow is waiting on the user.
- **Keyboard shortcuts dialog** (spec 008 FR-020, `KeyboardShortcutsDialog.tsx`, T023): a read-only list reachable from the profile menu, grouped under headings ("Message box", "Split view"), each row a plain-text action and its chord as `Kbd`/`KbdGroup` key-caps. Lists ONLY a chord individually verified to have a real working handler behind it (a keydown listener, a textarea default, or a native menu accelerator) -- several rows [`index.md`](index.md#keyboard)'s own "Keyboard" table documents are left out because no such handler exists yet (tracked as a GitHub issue, not silently dropped or promised as "coming soon"). Initial focus lands on the primary **Done** button.
- **Health check dialog** (spec 008 FR-022, `HealthCheckDialog.tsx`/`CheckRow.tsx`, T024; post-build review fixes, Stuart 2026-10-05): reachable from the profile menu, re-running the exact same `readiness.check()` the first-run Readiness screen uses and rendering each row through the same extracted `CheckRow.tsx` (icon, the real `found`/`hint` text exactly as returned, never an invented string or hard-coded version) -- the one difference is the state word ("Passed"/"Passed with a warning"/"Failed"/"Checking") shown visibly here rather than `sr-only` as on the quieter first-run screen, announced only once (`CheckStatusIcon`'s own `sr-only` word is suppressed here so a screen reader never hears it twice). Pass/warning/fail are never colour alone: icon plus that visible word every time, using the same `text-state-needs-you`/`text-state-working` design tokens every other state surface in the app uses (not a hard-coded colour), so a warning here always matches the same warning elsewhere under every theme including high contrast. A re-run keeps the previous results visible, dimmed (`opacity-60`) and `aria-busy`, instead of blanking every row, so the dialog never shrinks and **Check again** (labelled "Checking…" while a run is in flight, a fixed minimum width so it never moves) never drifts out from under a pointer that just clicked it; it is `aria-disabled` (keeping focus) while the primary **Done** button stays enabled. A thrown `readiness.check` (not just a returned failure) is caught: every row is marked failed with the hint "The check could not run. Try Check again.", exactly like the first-run Readiness screen's own catch, and an assertive region announces "Health check couldn't run." A polite region announces "Checking…" at the start and, on completion, counts failures and warnings separately so a pass-with-a-warning row is never reported as a failure: "Health check complete. All checks passed." with nothing to report, "Health check complete. All checks passed, {m} with a warning." (plural "warnings" for m>1) for warnings only, or "Health check complete. {n} failed." plus ", {m} passed with a warning" (plural as above) when any check failed. Also updates the shared health store (`useHealthStore`) the same way the Readiness screen does, so the status bar's low-memory-adjacent OMP-version notice stays in sync. The dialog is `sm:max-w-lg` (matching the other dialogs here) so a wrapped state word never orphans onto its own line.
- **Manage accounts** (spec 008 FR-008 to FR-011, FR-014, FR-016, `ManageAccountsDialog.tsx`/`AddAccountPanel.tsx`/`SignOutDialog.tsx`/`OmpProvidersSection.tsx`, T016/T017/T019): a `Dialog` (`sm:max-w-lg`, capped at `min(680px, 100vh-4rem)` tall with its own outer scroll so a short window never clips it -- measured 680px at an 800px-tall window, 436px and scrolling at a 500px-tall window, the close button always reachable) reachable only from the profile menu. While the account list itself is first loading, the GitHub section shows a spinner and "Checking GitHub sign-in…", with no Add account button (nothing is known signed in or not yet); if that read fails outright (`gh-failed`, or a thrown invoke, nothing cached), it instead shows an amber warning icon, "Couldn't read your GitHub CLI accounts.", and a **Check again** button, again with no Add account button, since offering to add a new account before the existing ones can even be read would be backwards. Otherwise it lists every GitHub CLI account under a **GitHub accounts** section header with its own **Add account** button (primary when the list is empty, outline otherwise, disabled while an add flow runs). Each row: avatar, display name (second line: `@login` and the host, each with a leading icon), the active row marked by both a left accent border and an inline check-icon **Active** label (never colour alone) and offering only **Sign out**; every other row offers **Switch** (outline) and **Sign out** (ghost, destructive text); a row whose GitHub CLI auth state is not `success` additionally shows an amber warning-icon status line -- "Sign-in expired." for an expired credential, "Couldn't reach GitHub." for an unreachable host, or "Sign-in needs attention." for any other cause -- and, in its trailing action cluster (ahead of Switch and Sign out): on an unreachable host, a **Check again** button (re-reads every account, `aria-disabled` while already running); otherwise, on `github.com`, a **Sign in again** button (`aria-disabled` while an add/sign-in flow is already running; any other host instead gets a plain `gh auth login --hostname <host>` instruction line, since the add flow is github.com-only). **Switch** is pessimistic: the row shows a spinning **Switching…** state and the active marker moves only once the GitHub CLI itself confirms (the row is projected immediately from the pre-mutation account list plus the CLI's own exit code, without waiting on a second `gh auth status` read, so the profile item updates in well under 1 second in practice -- measured 0.75 to 0.95 s, FR-010/SC-002's 1 s budget -- while a background `gh auth status` read then reconciles with the CLI's real state a moment later and rebroadcasts if it differs), since switching changes the identity the next pull request or update request uses; every other row's Switch button disables meanwhile. Add account runs inline directly under the section header and above the account list (never a nested dialog, and never pushed off-screen by a long list): a spinner while starting, then (typically within about 0.5 to 1 s) the one-time code grouped as `XXXX-XXXX` (shown exactly as received if the CLI's own code is already hyphenated or a different length) in the code font, a **Copy code** button (never auto-copies the code; copies through the main-process clipboard channel, since the sandboxed renderer denies the Clipboard API permission outright), a link to `https://github.com/login/device` for a browser-less machine, and **Cancel** (the GitHub CLI's own device-flow process does not exit on its own while cancelling, so Cancel shows a disabled **Cancelling…** state, keeping focus rather than losing it, for about 2 seconds until the process actually ends); a failed attempt shows main's own plain-language failure reason as an alert (never a guessed cause), falling back to "Sign-in did not finish." when none is given, with **Retry** focused beside it. A completed add/re-auth flow announces "Added GitHub account {name}" or "Re-authenticated {name}" (or "Re-authenticated with GitHub" if no matching account could be found), appending " It is now the active account." whenever that flow changed which account is active, and moves focus to the new or re-authenticated account's own Sign out button. The first Esc while a flow is running cancels it instead of closing the dialog (a second Esc then closes it), and closing the dialog by any other means while a flow runs also cancels it. Sign-out confirmation (FR-011) is one shared `AlertDialog` reachable from here or from the profile menu's own Sign out item, naming the account and, when it is the active one, which account becomes active next (or that none will) before confirming; closing either dialog by any means always returns keyboard focus somewhere live -- the profile item's name button when launched from the menu, or the relevant Manage accounts row/button otherwise -- never `<body>`. No GitHub account signed in shows an empty-state message with **Add account** as the primary action; GitHub CLI missing shows an **Install GitHub CLI** link instead of the account list, with no Add account button. Below a decorative separator, a read-only **OMP provider sign-in** section (FR-016, research.md Decision 6 -- OMP has no `/login`/`/logout` over its own rpc-ui connection, so this never offers an in-app sign-in/out action and never mentions `/logout`): initial open shows a skeleton (three rows, "Checking OMP providers…", `aria-busy`) while a scratch `omp` process reads the list (measured 4.7 s direct, about 4 to 8 s end to end in the app) -- dialog-open focus stays on the GitHub section's Add account button throughout, never moving to this section.
